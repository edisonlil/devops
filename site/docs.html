什么是 DevOps 工具

DevOps 是一款企业级的 CI/CD 自动化部署工具，旨在简化应用的构建、打包和部署流程。

为什么选择 DevOps？

🚀

一键部署

从代码拉取到容器化部署，一条命令搞定

🎯

新手友好

交互式引导，即使是运维小白也能快速上手

🔧

多语言支持

支持 Java、Vue.js、Go、Python 等主流技术栈

☸️

企业级

完整的 Kubernetes 和 Harbor 集成

核心概念

在开始使用 DevOps 之前，让我们了解几个核心概念：

🏗️ 工作空间 (Workspace)

工作空间是项目的隔离环境，每个工作空间都有独立的配置文件、模板和部署设置。这样可以确保不同项目之间不会相互影响。

示例：你可以为前端项目创建一个 "frontend" 工作空间，为后端 API 创建一个 "backend" 工作空间。

📦 模板系统

模板定义了应用的部署配置，包括 Dockerfile 和 Kubernetes 配置文件。DevOps 提供了常用的模板，你也可以创建自定义模板。

示例：spring-boot 模板包含了 Java 应用的标准部署配置。

🔄 构建流程

DevOps 的构建流程包括：代码拉取 → 依赖安装 → 编译构建 → Docker 镜像构建 → 推送到仓库 → 部署到集群。

示例：Java 项目会自动使用 Maven 或 Gradle 进行构建。

安装指南

📋 系统要求

Python版本要求

DevOps工具需要Python环境来支持模板渲染和中间件部署功能：

  • Python 3.6+: 支持基本功能
  • Python 3.7+: 推荐版本，支持所有功能

Python依赖包

安装完成后，需要安装以下Python依赖：

# 对于Python 3.6 pip3 install "PyYAML>=5.1,<7.0" "Jinja2>=2.10,<3.1" # 对于Python 3.7+（推荐） pip3 install "PyYAML>=5.4.1" "Jinja2>=2.11.0" # 或者使用用户模式安装 pip3 install --user PyYAML Jinja2
注意: 如果遇到依赖安装问题，请确保Python版本符合要求。Python 3.6用户需要使用较低版本的Jinja2。

DevOps 提供了三种安装模式，根据你的需求选择合适的方式：

🎯 标准安装（推荐）

适合 Java 开发和容器化部署，包含 Java 环境、Maven/Gradle、Docker 等工具。

curl -fsSL https://github.com/edisonlil/devops/raw/refs/heads/dev/install.sh | bash
⏱️ 安装时间：~10分钟 💾 磁盘占用：~3GB

📦 完整安装

适合全栈开发，包含所有开发工具：Java、Node.js、Go 等。

curl -fsSL https://github.com/edisonlil/devops/raw/refs/heads/dev/install.sh | bash -s -- --full
⏱️ 安装时间：~20分钟 💾 磁盘占用：~5GB

⚡ 脚本专用

适合已有开发环境的用户，只安装 DevOps 脚本。

curl -fsSL https://github.com/edisonlil/devops/raw/refs/heads/dev/install.sh | bash -s -- --script-only
⏱️ 安装时间：~1分钟 💾 磁盘占用：~20MB

验证安装

安装完成后，运行以下命令验证：

# 重新加载环境变量 source ~/.bashrc # 检查 DevOps 版本 devops --help # 检查开发工具状态 devops install-tools --check

第一次部署

让我们通过一个简单的例子来体验 DevOps 的强大功能。

1

创建工作空间

首先创建一个工作空间来隔离项目环境：

devops create workspace demo -i
提示：使用 -i 参数启用交互式创建，系统会引导你完成配置。
2

部署示例应用

使用交互式模式部署一个 Java 应用：

devops run java hello-world -i
说明：系统会提示你输入 Git 地址、构建工具等信息。对于新手，建议使用交互式模式。
3

查看部署结果

部署完成后，你可以看到类似的输出：

✅ 代码拉取成功
✅ Maven 构建完成
✅ Docker 镜像构建成功
✅ 部署到 Kubernetes 完成
🌐 应用访问地址：http://your-cluster:30080

🎉 恭喜！

你已经成功完成了第一次部署。接下来可以探索更多高级功能，比如多端口配置、版本管理等。

工作空间管理

工作空间是 DevOps 的核心概念，它为不同的项目提供隔离的配置环境。

创建工作空间

# 交互式创建（推荐新手） devops create workspace myproject -i # 非交互式创建 devops create workspace myproject --git-url https://github.com/example/repo.git

工作空间配置

每个工作空间都有一个配置文件 workspace/{name}/config，包含以下主要配置：

部署平台配置

配置项 说明 示例
BUILD_PLATFORM 部署平台类型 KUBERNETES | DOCKER_SWARM | DOCKER_COMPOSE | SHELL
BUILD_K8S_NAMESPACE Kubernetes命名空间 default
BUILD_DOCKER_STACK_NAME Docker Swarm 栈名称 default
BUILD_DOCKER_SWARM_NETWORK Docker Swarm 网络名称 swarm-network

Harbor仓库配置

配置项 说明 示例
BUILD_ENABEL_HARBOR 启用Harbor仓库 1(启用)/0(禁用)
BUILD_HARBOR_ADDRESS Harbor仓库地址 harbor.example.com
BUILD_HARBOR_PROJECT Harbor项目名称 myproject
BUILD_HARBOR_USERNAME Harbor访问用户名 admin
BUILD_HARBOR_PASSWORD Harbor访问密码 Harbor12345

代码管理配置

配置项 说明 示例
BUILD_GIT_URL Git默认地址 http://github.com/xxx/xxx
BUILD_GIT_BRANCH Git默认分支 main
BUILD_GIT_USERNAME Git 默认用户名（可选，用于 HTTP/HTTPS 自动认证） robot-user
BUILD_GIT_PASSWORD Git 默认密码/Token（可选，建议使用环境变量引用） ${GIT_TOKEN}

构建工具配置

配置项 说明 示例
BUILD_MAVEN_SETTINGS Maven settings文件路径 settings.xml 路径
BUILD_GRADLE_INIT_SCRIPT Gradle 初始化脚本路径 init.gradle 路径
BUILD_VERSION 构建工具版本配置 node:18.12,jdk:17,maven:3.9.3
BUILD_JAVA_OPTS 默认 Java 启动参数（命令行 --java-opts 未指定时生效） -Xms512m -Xmx1024m -Dspring.profiles.active=prod

前端项目配置

配置项 说明 示例
BUILD_VUE_REGISTRY Vue项目npm镜像库 https://registry.npmmirror.com
💡 提示：工作空间配置支持团队共享，可以确保团队成员使用相同的部署环境。新增 BUILD_JAVA_OPTS（默认 JVM 参数）、BUILD_GIT_USERNAME/BUILD_GIT_PASSWORD（HTTP(S) Git 自动认证）；BUILD_ENABEL_DOCKERFILES 已弃用并移除。

Java 应用部署

DevOps 对 Java 应用提供了完整的支持，包括 Maven 和 Gradle 构建工具。

基础部署

# 使用 Maven 构建 devops run java \ --git-url https://github.com/example/spring-app.git \ --build-tool maven \ my-app # 使用 Gradle 构建 devops run java \ --git-url https://github.com/example/spring-app.git \ --build-tool gradle \ my-app

高级配置

# 指定 JVM 参数和端口 devops run java \ --git-url https://github.com/example/spring-app.git \ --java-opts "-Xmx512m -Dspring.profiles.active=prod" \ --app-port 8080 \ --expose-port 30080 \ my-app

🔧 构建工具自动检测

DevOps 会自动检测项目中的构建文件：

  • Maven：检测 pom.xml 文件
  • Gradle：检测 build.gradle 或 build.gradle.kts 文件
提示：如果项目同时包含两种构建文件，可以使用 --build-tool 参数明确指定。

Vue.js 应用部署

DevOps 支持 Vue.js 前端应用的自动化构建和部署，包括依赖安装、构建优化和 Nginx 配置。

基础部署

# 基础 Vue 项目部署 devops run vue \ --git-url https://github.com/example/vue-app.git \ --template vue-nginx \ my-frontend

镜像库配置

通过工作空间配置指定 npm 镜像库，加速依赖下载：

# 在 workspace/config 中添加 BUILD_VUE_REGISTRY="https://registry.npmmirror.com" # 部署时自动应用配置 devops run vue \ --git-url https://github.com/example/vue-app.git \ my-frontend

常用镜像库地址

  • 阿里云：https://registry.npmmirror.com
  • 淘宝：https://registry.npm.taobao.org
  • 官方：https://registry.npmjs.org

多环境构建

# 生产环境构建 devops run vue \ --git-url https://github.com/example/vue-app.git \ --build-env "prod" \ --expose-port 30081 \ my-frontend # 自定义构建命令 devops run vue \ --git-url https://github.com/example/vue-app.git \ --build-cmds "npm run build:production" \ my-frontend

📦 构建流程

Vue.js 应用的完整构建流程：

  1. 代码拉取：从 Git/SVN 仓库拉取源码
  2. 依赖安装：执行 npm install 或 yarn install
  3. 项目构建：执行 npm run build 或自定义命令
  4. Nginx 配置：自动生成 Nginx 配置文件
  5. 容器化：构建 Docker 镜像并部署

Python 应用部署

DevOps 支持 Python 应用的自动化部署，包括 Flask、Django、FastAPI 等主流框架。

基础部署

# Flask 应用部署 devops run python \ --git-url https://github.com/example/flask-api.git \ --python-main app.py \ --service-port "5000" \ my-api # Django 应用部署 devops run python \ --git-url https://github.com/example/django-web.git \ --python-main manage.py \ --service-port "8000" \ my-web # FastAPI 应用部署 devops run python \ --git-url https://github.com/example/fastapi-service.git \ --python-main main.py \ --service-port "8000" \ my-service

Python 版本管理

# 使用 conda 管理 Python 版本 devops run python \ --git-url https://github.com/example/python-app.git \ --build-version "python:3.11" \ my-app # 使用 pyenv 管理版本 devops run python \ --git-url https://github.com/example/python-app.git \ --build-version "py:3.10" \ my-app

高级配置

# 完整的 Python 应用配置 devops run python \ --git-url https://github.com/example/python-app.git \ --python-main server.py \ --python-requirements requirements/prod.txt \ --build-version "python:3.11" \ --build-env prod \ --service-port "http:5000,admin:9090" \ --export-port "5000:30050,9090:30090" \ --namespace production \ my-app

🐍 Python 特定参数

参数 说明 默认值
--python-main 主程序文件路径 app.py
--python-requirements requirements 文件路径 requirements.txt

🎯 最佳实践

Python 应用部署建议：

  • 使用虚拟环境管理依赖（conda/pyenv）
  • 固定依赖版本号在 requirements.txt 中
  • 添加健康检查端点 /health
  • 使用环境变量管理配置
  • 生产环境使用 WSGI/ASGI 服务器

中间件部署

DevOps 提供开箱即用的中间件部署功能，支持 Redis、MySQL、Kafka 等常用基础设施服务的一键部署和管理。

📋 环境要求

Python版本要求：中间件部署功能需要Python环境支持模板渲染

  • Python 3.6+: 支持基本功能
  • Python 3.7+: 推荐版本，支持所有功能

依赖包安装：

# 安装Python依赖 pip3 install --user PyYAML Jinja2 # 或者根据Python版本选择 # Python 3.6: pip3 install "PyYAML>=5.1,<7.0" "Jinja2>=2.10,<3.1" # Python 3.7+: pip3 install "PyYAML>=5.4.1" "Jinja2>=2.11.0"

支持的中间件类型

🗄️ 缓存服务

  • redis-standalone - Redis单实例
  • redis-cluster - Redis集群
  • redis-sentinel - Redis哨兵模式

🗃️ 数据库服务

  • mysql-standalone - MySQL单实例
  • mysql-ha - MySQL高可用
  • postgresql-standalone - PostgreSQL单实例
  • postgresql-ha - PostgreSQL高可用

📨 消息队列

  • kafka-standalone - Kafka单节点
  • kafka-cluster - Kafka集群
  • rabbitmq-standalone - RabbitMQ单实例
  • rabbitmq-cluster - RabbitMQ集群

快速开始

部署 Redis 缓存服务

# 交互式部署（推荐） devops run middleware redis-standalone cache-server -i # 动态参数部署 - 参数名对应模板变量 devops run middleware redis-standalone cache-server \ --memory-limit 2Gi \ --storage-size 5Gi \ --redis-password mypassword # 完整配置 - 所有参数都是动态匹配 devops run middleware redis-standalone cache-server \ --memory-limit 4Gi \ --storage-size 20Gi \ --redis-password securepass123 \ --redis-persistence both \ --max-memory-policy allkeys-lru \ --export-port 30379

💡 动态参数说明

参数名称直接对应模板中的变量名：

  • cache-server → {{ instance_name }}（自动复用命令中的名称）
  • --memory-limit → {{ memory_limit }}
  • --redis-password → {{ redis_password }}
  • --redis-persistence → {{ redis_persistence }}

用户可以传递任意 --变量名 参数，只要模板中有对应的变量就会生效。instance_name 会自动复用命令中的实例名称。

部署 MySQL 数据库

# 交互式部署 devops run middleware mysql-standalone main-db -i # 命令行部署 - 基础配置 devops run middleware mysql-standalone main-db \ --memory-limit 4Gi \ --storage-size 100Gi \ --mysql-database app_db \ --mysql-user app_user # 命令行部署 - 完整配置 devops run middleware mysql-standalone main-db \ --memory-limit 8Gi \ --storage-size 500Gi \ --mysql-root-password rootpass123 \ --mysql-database production_db \ --mysql-user webapp_user \ --mysql-password userpass123 \ --mysql-charset utf8mb4 \ --export-port 30306

中间件管理

部署完成后，可以使用以下命令管理中间件服务：

# 列出已部署的中间件 devops middleware list # 查看中间件状态 devops middleware status cache-server # 查看中间件日志 devops middleware logs cache-server --follow # 扩缩容中间件（支持集群模式） devops middleware scale cache-cluster --replicas 6 # 备份中间件数据 devops middleware backup main-db # 删除中间件 devops middleware remove cache-server

通用参数

参数 说明 示例
--memory-limit 内存限制 2Gi, 512Mi
--storage-size 存储大小 10Gi, 100Gi
--replicas 副本数量 1, 3, 6
--export-port 外部访问端口 30379, 30306
--namespace Kubernetes命名空间 middleware, production

中间件特定参数

Redis 参数

参数 说明 选项
--redis-password Redis访问密码 自定义密码或auto-generate
--redis-persistence 持久化类型 rdb, aof, both, none
--max-memory-policy 内存淘汰策略 allkeys-lru, volatile-lru

MySQL 参数

参数 说明 示例
--mysql-root-password root用户密码 自定义密码或auto-generate
--mysql-database 初始数据库名 app_db, production_db
--mysql-user 应用用户名 app_user, web_user
--mysql-charset 字符集 utf8mb4, utf8, latin1

🎯 连接信息

部署完成后，系统会自动显示连接信息：

  • 内部访问：service-name.namespace.svc.cluster.local:port
  • 外部访问：node-ip:export-port（如果配置了外部端口）
  • 密码信息：存储在 Kubernetes Secret 中
  • 管理命令：使用 devops middleware 命令管理

📁 模板目录结构

中间件模板按以下结构组织：

  • 全局模板：templates/{platform}/middleware/{template-name}/
  • 工作空间模板：workspace/{workspace}/templates/{platform}/middleware/{template-name}/
  • 应用模板：templates/{platform}/app/{template-name}/

例如：templates/k8s/middleware/redis-standalone/

⚠️ 注意事项

  • 生产环境建议使用集群模式以确保高可用
  • 定期备份重要数据，使用 devops middleware backup 命令
  • 合理配置资源限制，避免影响其他服务
  • 使用强密码并妥善保管访问凭据

交互式部署

交互式部署是 DevOps 的特色功能，特别适合新手用户和需要逐步配置的场景。

启动交互式模式

# 完全交互式（会提示选择类型和项目名） devops run -i # 指定类型的交互式部署 devops run java -i devops run vue my-app -i devops run python my-api -i # 中间件交互式部署（新功能） devops run middleware -i devops run middleware redis-standalone my-redis -i

🆕 中间件交互式部署升级

中间件交互式部署功能已升级，现在支持：

  • 动态模板选择：自动扫描可用的中间件模板
  • 基于元数据的配置：根据模板的 metadata.yaml 自动生成配置界面
  • 智能默认值：有默认值的变量显示为 变量描述 (默认: 默认值):
  • 非必填处理：有默认值的变量变为非必填，用户可直接回车使用默认值
环境要求：中间件交互式部署需要 Python 3.6+ 和相关依赖包（PyYAML, Jinja2）

交互式流程

1

选择部署类型

系统会提示选择应用类型：Java、Vue.js、Go、Python、Nginx 或 Tomcat

2

输入项目信息

输入项目名称、Git 地址等基本信息，系统会显示 workspace 的默认值

3

配置构建参数

配置构建工具、版本、环境变量等参数，支持智能提示和验证

4

确认并执行

预览生成的命令，确认无误后开始执行部署

🎯 智能默认值

交互式模式的智能特性：

  • 显示默认值：自动显示 workspace 配置的默认值
  • 参数验证：实时验证输入参数的有效性
  • 智能提示：根据项目类型提供相关建议
  • 命令预览：显示等效的命令行形式

Python 环境管理

DevOps 优先使用 Conda 进行 Python 环境管理，提供更好的包管理和环境隔离：

多端口配置

DevOps 支持灵活的多端口配置，包括多容器支持、智能端口映射、自动 containerPort 同步等高级功能。

🚀 新增功能

  • 多容器支持：智能识别主容器，支持指定容器的端口配置
  • 自动同步：自动同步 Deployment containerPort 和 Service 端口
  • Sidecar识别：自动排除 Istio、日志收集等 sidecar 容器
  • 显式映射：精确控制 servicePort:nodePort 映射关系

端口配置参数

参数 说明 示例
--service-port 服务端口，支持多端口、命名端口、容器指定 8080,9090 或 http:8080,admin:9090 或 web-app:http:8080,api:api:3000
--export-port 导出端口（NodePort），支持显式映射 30080,30090 或 8080:30080,9090:30090 或 30080,9090:30090,30300
--app-port 传统单应用端口（向后兼容） 8080
--expose-port 传统单导出端口（向后兼容） 30080

使用示例

基础多端口配置

# 多端口配置（顺序映射） devops run java \ --service-port "http:8080,admin:9090,health:9091" \ --export-port "30080,30090,30091" \ webapp # 显式端口映射 devops run java \ --service-port "http:8080,admin:9090" \ --export-port "8080:30080,9090:30090" \ api

多容器端口配置

# 指定容器的端口配置 devops run java \ --service-port "web-app:http:8080,api-service:api:3000,monitoring:metrics:9090" \ --export-port "8080:30080,3000:30300" \ microservice # 混合容器指定和默认配置 devops run java \ --service-port "http:8080,api-service:api:3000" \ --export-port "30080,30300" \ my-app

高级映射示例

# 混合显式映射和顺序映射 devops run java \ --service-port "web:8080,admin:9090,api:3000,metrics:4000" \ --export-port "9090:31090,30080,4000:31400,30300" \ complex-app # 结果： # web:8080 → NodePort 30080 (顺序映射) # admin:9090 → NodePort 31090 (显式映射) # api:3000 → NodePort 30300 (顺序映射) # metrics:4000 → NodePort 31400 (显式映射)

🌐 端口映射规则

DevOps 的智能端口映射：

  • 显式优先："service-port:node-port"格式的显式映射优先于顺序映射
  • 一一对应：未指定显式映射时，服务端口和导出端口按顺序对应
  • 部分映射：支持只导出部分服务端口，未映射端口仅集群内部可访问
  • 自动类型：有导出端口时自动设置 Service 类型为 NodePort
  • 名称支持：可使用命名端口进行映射（如 admin:30090）

🐳 多容器支持

智能处理多容器场景：

  • 主容器识别：自动识别并排除 Istio、Fluentd、Prometheus 等 sidecar 容器
  • 容器指定：使用 "容器名:端口名:端口号" 格式指定特定容器的端口
  • 自动同步：自动添加缺失的 containerPort，更新端口名称
  • 避免冲突：智能检测端口冲突，不重复添加已存在的端口
  • 混合配置：支持部分端口指定容器，部分使用默认主容器

💡 最佳实践

多容器场景推荐配置：

# Istio 服务网格环境 devops run java \ --service-port "http:8080,admin:9090" \ --export-port "8080:30080" \ my-service # 系统会自动： # 1. 识别 istio-proxy 为 sidecar，跳过 # 2. 将端口配置到主应用容器 # 3. 自动添加缺失的 containerPort # 4. 同步 Service 端口配置

💻 命令行参数传递

DevOps 支持动态的命令行参数传递，用户可以传递任意 --变量名 格式的参数，系统会自动匹配模板中的变量：

动态参数格式

参数格式规则：

  • 格式：--变量名 值
  • 变量名：与模板中 {{ 变量名 }} 或 metadata.yaml 中定义的变量名一致
  • 自动转换：--memory-limit → memory_limit
  • 布尔参数：--enable-auth（无值时默认为true）
  • 实例名称：instance_name 自动复用命令中的 <name> 参数

基于模板变量的参数传递

参数名称直接对应模板中的变量名，无需预定义：

# 模板中定义的变量：{{ memory_limit }}, {{ redis_password }} # 对应的命令行参数： --memory-limit 2Gi # 对应 {{ memory_limit }} --redis-password mypass # 对应 {{ redis_password }} --storage-size 100Gi # 对应 {{ storage_size }} --replicas 3 # 对应 {{ replicas }} --export-port 30379 # 对应 {{ export_port }}

实际使用示例

# Redis部署 - 参数名对应模板变量 devops run middleware redis-standalone cache-server \ --memory-limit 2Gi \ --storage-size 10Gi \ --redis-password mypassword \ --redis-persistence both \ --max-memory-policy allkeys-lru \ --export-port 30379 # MySQL部署 - 参数名对应模板变量 devops run middleware mysql-standalone main-db \ --memory-limit 4Gi \ --storage-size 100Gi \ --mysql-root-password rootpass123 \ --mysql-database app_db \ --mysql-user app_user \ --mysql-password userpass123 # 自定义模板 - 任意变量名都支持 devops run middleware custom-redis my-cache \ --custom-config-value "some value" \ --enable-monitoring true \ --backup-schedule "0 2 * * *"

变量名匹配规则

参数名与模板变量的对应关系：

命令行参数 模板变量 说明
<name> {{ instance_name }} 自动复用命令中的实例名称
--memory-limit {{ memory_limit }} 自动转换连字符为下划线
--redis-password {{ redis_password }} 直接对应模板变量
--mysql-root-password {{ mysql_root_password }} 支持复杂变量名
--custom-config {{ custom_config }} 任意自定义变量

动态参数工作原理

参数处理流程：

  1. 解析metadata.yaml：读取变量定义和默认值
  2. 提取模板变量：扫描deploy.yaml中的 {{ 变量名 }}
  3. 匹配命令行参数：--变量名 自动匹配对应变量
  4. 应用优先级：命令行参数 > metadata默认值 > 系统默认值
# 示例：动态参数匹配 # metadata.yaml中定义： variables: - name: "custom_timeout" default: "30s" - name: "enable_ssl" default: "false" # 模板中使用： name: {{ instance_name }}-config # 自动使用命令中的 timeout: {{ custom_timeout }} ssl_enabled: {{ enable_ssl }} # 命令行传递： devops run middleware my-service my-instance \ --custom-timeout 60s \ # 覆盖默认值30s --enable-ssl true \ # 覆盖默认值false --new-variable value # 新变量，如果模板中有{{ new_variable }}就会生效 # 结果：instance_name = "my-instance"（自动复用）

以下是创建自定义Redis集群模板的完整示例：

1. 创建模板目录

mkdir -p workspace/myproject/templates/k8s/middleware/redis-cluster

2. 创建metadata.yaml

# workspace/myproject/templates/k8s/middleware/redis-cluster/metadata.yaml name: "redis-cluster" type: "redis" description: "Redis集群部署模板，支持3-6个节点" version: "1.0" variables: - name: "cluster_nodes" type: "integer" default: 6 description: "集群节点数量" validation: "value >= 3 && value <= 6" - name: "memory_limit" type: "string" default: "1Gi" description: "每个节点内存限制" - name: "redis_password" type: "string" default: "auto-generate" description: "Redis集群密码" ports: - name: "redis" port: 6379 - name: "cluster-bus" port: 16379

3. 创建deploy.yaml（支持Jinja2）

# workspace/myproject/templates/k8s/middleware/redis-cluster/deploy.yaml apiVersion: v1 kind: ConfigMap metadata: name: {{ instance_name }}-redis-config namespace: {{ namespace }} data: redis.conf: | port 6379 cluster-enabled yes cluster-config-file nodes.conf cluster-node-timeout 5000 {% if redis_password %} requirepass {{ redis_password }} masterauth {{ redis_password }} {% endif %} --- apiVersion: apps/v1 kind: StatefulSet metadata: name: {{ instance_name }}-redis namespace: {{ namespace }} spec: serviceName: {{ instance_name }}-redis-headless replicas: {{ cluster_nodes }} selector: matchLabels: app: {{ instance_name }}-redis template: metadata: labels: app: {{ instance_name }}-redis spec: containers: - name: redis image: redis:7-alpine ports: - containerPort: 6379 - containerPort: 16379 resources: limits: memory: {{ memory_limit }} requests: memory: {{ memory_limit | replace('Gi', '0.7Gi') | replace('Mi', '0.7Mi') }} volumeMounts: - name: config mountPath: /usr/local/etc/redis/redis.conf subPath: redis.conf volumes: - name: config configMap: name: {{ instance_name }}-redis-config

4. 使用自定义模板

# 使用自定义Redis集群模板 devops run middleware redis-cluster my-cluster \ --workspace myproject \ --cluster-nodes 6 \ --memory-limit 2Gi \ --redis-password mypassword

⚠️ 模板开发注意事项

  • 文件后缀名：使用 .yaml.j2 (Jinja2) 或 .yaml.tpl (占位符) 明确标识模板类型
  • Jinja2语法：中间件模板支持完整的Jinja2语法，包括条件、循环、过滤器
  • 向后兼容：.yaml 文件仍然支持，但推荐使用明确的后缀名
  • 变量命名：使用下划线命名法，避免与系统变量冲突
  • metadata.yaml：中间件模板必须包含metadata.yaml文件定义变量
  • 测试验证：开发完成后使用 devops template validate 验证语法
  • 版本管理：建议在metadata.yaml中标明版本号

问题：无法连接到 Kubernetes 集群

解决方案：

# 检查 kubectl 配置 kubectl config current-context # 测试集群连接 kubectl get nodes # 检查 kubeconfig 文件 ls -la ~/.kube/config

调试模式

启用调试模式可以获得更详细的错误信息：

# 启用调试模式 export DEBUG=true devops run java my-app # 或者使用环境变量 DEBUG=true devops run java my-app

获取帮助

# 查看帮助信息 devops --help # 查看特定命令帮助 devops run --help devops template --help # 检查工具状态 devops install-tools --check
