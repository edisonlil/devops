# 工作空间管理

工作空间（Workspace）是 DevOps 的核心概念，用于管理项目配置、团队设置和环境信息。

## 🎯 工作空间概念

### 什么是工作空间？

工作空间是一个配置容器，包含：

- **项目配置**: Git 仓库、分支、构建设置
- **环境配置**: 部署平台、命名空间、Harbor 信息
- **团队设置**: 默认版本、构建工具配置
- **部署模板**: 自定义的部署模板和参数

### 工作空间的优势

- **配置复用**: 避免重复输入相同的配置参数
- **团队协作**: 统一团队的开发和部署标准
- **环境隔离**: 不同项目和环境使用独立的配置
- **版本管理**: 锁定特定版本确保环境一致性

## 📁 工作空间结构

```bash
workspace/
├── default/                    # 默认工作空间
│   ├── config                 # 配置文件
│   └── README.md              # 说明文档
├── my-team/                   # 团队工作空间
│   ├── config                 # 团队配置
│   ├── templates/             # 自定义模板
│   └── README.md              # 团队说明
└── production/                # 生产环境工作空间
    ├── config                 # 生产配置
    └── README.md              # 生产环境说明
```

## 🏗️ 创建工作空间

### 交互式创建

```bash
# 交互式创建工作空间
devops create workspace my-team -i

# 系统会引导您配置：
# 1. 部署平台选择
# 2. Git 仓库信息
# 3. Harbor 镜像仓库
# 4. 默认命名空间
# 5. 构建工具版本
# 6. 是否设为默认
```

### 非交互式创建

```bash
# 创建开发团队工作空间
devops create workspace dev-team \
  --platform KUBERNETES \
  --namespace dev \
  --git-url https://git.company.com \
  --git-branch main \
  --harbor-address harbor.company.com \
  --harbor-project dev-project \
  --build-version "jdk:17,maven:3.9.3,node:18.12" \
  --set-default

# 创建生产环境工作空间
devops create workspace production \
  --platform KUBERNETES \
  --namespace production \
  --git-url https://git.company.com \
  --git-branch release \
  --harbor-address harbor.company.com \
  --harbor-project prod-project \
  --build-version "jdk:11,maven:3.8.6,node:16.20"
```

## ⚙️ 工作空间配置

### 配置文件格式

工作空间配置文件 `workspace/{name}/config`：

```bash
# 部署平台配置
BUILD_PLATFORM="KUBERNETES"

# Git 配置
BUILD_GIT_URL="https://git.company.com"
BUILD_GIT_BRANCH="main"

# Harbor 配置
BUILD_HARBOR_ADDRESS="harbor.company.com"
BUILD_HARBOR_PROJECT="my-project"
BUILD_HARBOR_USERNAME="robot$project+deploy"
BUILD_HARBOR_PASSWORD="your-robot-token"

# Kubernetes 配置
BUILD_NAMESPACE="dev"

# 构建工具版本
BUILD_VERSION="jdk:17,maven:3.9.3,node:18.12"

# 构建环境
BUILD_ENV="dev"

# Java 配置（默认启动参数）
BUILD_JAVA_OPTS="-Xmx1g -Xms512m"

# 自定义构建命令
BUILD_CMDS="mvn clean package -DskipTests"
```

### 配置项说明

| 配置项 | 说明 | 示例 |
|--------|------|------|
| `BUILD_PLATFORM` | 部署平台 | `KUBERNETES`, `SWARM` |
| `BUILD_GIT_URL` | 默认 Git 地址 | `https://git.company.com` |
| `BUILD_GIT_BRANCH` | 默认分支 | `main`, `develop` |
| `BUILD_HARBOR_ADDRESS` | Harbor 地址 | `harbor.company.com` |
| `BUILD_HARBOR_PROJECT` | Harbor 项目 | `my-project` |
| `BUILD_NAMESPACE` | 默认命名空间 | `dev`, `production` |
| `BUILD_VERSION` | 构建工具版本 | `jdk:17,maven:3.9.3` |
| `BUILD_ENV` | 构建环境 | `dev`, `test`, `prod` |
| `BUILD_JAVA_OPTS` | Java 启动参数默认值 | `-Xms512m -Xmx1024m` |
| `BUILD_GIT_USERNAME` | Git 默认用户名（可选） | `robot-user` |
| `BUILD_GIT_PASSWORD` | Git 默认密码/Token（可选） | `${GIT_TOKEN}` |

### Java 启动参数默认值

在工作空间中可以配置默认的 JVM 启动参数，命令行未显式传入 `--java-opts` 时使用：

```bash
# workspace/{name}/config
BUILD_JAVA_OPTS="-Xms512m -Xmx1024m -Dspring.profiles.active=prod"
```

优先级：命令行 `--java-opts` > 工作空间 `BUILD_JAVA_OPTS`。

> 说明：原 `JAVA_OPTS` 配置示例已统一为 `BUILD_JAVA_OPTS`。

### Git 默认凭据与自动登录

当配置了 `BUILD_GIT_USERNAME` 与 `BUILD_GIT_PASSWORD` 且使用 HTTP/HTTPS Git 地址时，拉取代码会自动注入凭据完成认证：

```bash
# workspace/{name}/config
BUILD_GIT_URL="https://git.company.com/group/repo.git"
BUILD_GIT_USERNAME="robot$project+read"
BUILD_GIT_PASSWORD="${GIT_READ_TOKEN}"
```

注意：

- 建议使用只读 Token 或机器人账号，不要使用个人密码。
- 凭据仅对 HTTP/HTTPS 生效；SSH 地址（git@...）请使用 SSH key。

### 变更与兼容性

- 新增：`BUILD_JAVA_OPTS` 用于配置默认的 Java 启动参数。
- 新增：`BUILD_GIT_USERNAME`、`BUILD_GIT_PASSWORD`，HTTP(S) Git 自动登录。
- 移除：已弃用的 `BUILD_ENABEL_DOCKERFILES` 参数与相关逻辑已删除，不再生效。

## 📋 复制工作空间

### 交互式复制

```bash
# 交互式复制工作空间
devops copy workspace demo demo-test -i

# 系统会引导您：
# 1. 确认是否覆盖已存在的目标工作空间
# 2. 选择是否修改部署平台
# 3. 配置新的命名空间或Stack名称
# 4. 修改Harbor项目名称
# 5. 是否设为默认工作空间
```

### 非交互式复制

```bash
# 复制工作空间并修改配置
devops copy workspace demo demo-prod \
  --namespace production \
  --harbor-project prod-project \
  --set-default

# 复制到不同平台
devops copy workspace k8s-demo swarm-demo \
  --platform DOCKER_SWARM \
  --stack demo-stack \
  --network demo_overlay_network

# 简单复制（保持所有配置不变）
devops copy workspace demo demo-backup
```

### 复制功能特点

- **完整复制**: 复制整个工作空间目录，包括配置文件、模板、部署文件等
- **配置修改**: 支持在复制过程中修改关键配置项
- **智能提示**: 交互模式下显示当前配置并提示修改
- **安全检查**: 目标工作空间存在时会提示确认覆盖

### 常见使用场景

```bash
# 场景1: 创建测试环境工作空间
devops copy workspace production test \
  --namespace test \
  --harbor-project test-project

# 场景2: 为不同团队创建独立工作空间
devops copy workspace frontend-base frontend-team-a \
  --namespace frontend-a \
  --harbor-project team-a-frontend

# 场景3: 从K8s环境复制到Docker Swarm
devops copy workspace k8s-prod swarm-prod \
  --platform DOCKER_SWARM \
  --stack prod-stack \
  --network prod_overlay_network

# 场景4: 快速备份工作空间
devops copy workspace production production-backup-$(date +%Y%m%d)
```

### 支持的配置修改

| 参数 | 说明 | 适用平台 |
|------|------|----------|
| `--platform` | 修改部署平台 | 全部 |
| `--namespace` | 修改K8s命名空间 | KUBERNETES |
| `--stack` | 修改Docker Stack名称 | DOCKER_SWARM/COMPOSE |
| `--network` | 修改网络名称 | DOCKER_SWARM/COMPOSE |
| `--harbor-project` | 修改Harbor项目 | 启用Harbor时 |
| `--set-default` | 设为默认工作空间 | 全部 |

## 🔄 工作空间管理

### 查看工作空间

```bash
# 查看所有工作空间
ls workspace/

# 查看当前工作空间信息
devops env info

# 查看特定工作空间配置
cat workspace/my-team/config
```

### 切换工作空间

```bash
# 切换到指定工作空间
devops env use my-team

# 切换到生产环境工作空间
devops env use production

# 查看当前使用的工作空间
devops env info | grep "Current Workspace"
```

### 编辑工作空间配置

```bash
# 编辑工作空间配置
vim workspace/my-team/config

# 或使用其他编辑器
nano workspace/my-team/config
code workspace/my-team/config
```

## 👥 团队协作

### 团队工作空间设置

```bash
# 创建团队标准工作空间
devops create workspace frontend-team \
  --platform KUBERNETES \
  --namespace frontend \
  --git-url https://git.company.com/frontend \
  --build-version "node:18.12" \
  --harbor-address harbor.company.com \
  --harbor-project frontend-project
```

团队配置文件示例：

```bash
# workspace/frontend-team/config

# 前端团队标准配置
BUILD_PLATFORM="KUBERNETES"
BUILD_GIT_URL="https://git.company.com/frontend"
BUILD_GIT_BRANCH="main"
BUILD_VERSION="node:18.12"
BUILD_ENV="dev"
BUILD_NAMESPACE="frontend"

# Harbor 配置
BUILD_HARBOR_ADDRESS="harbor.company.com"
BUILD_HARBOR_PROJECT="frontend-project"

# 前端构建配置
BUILD_CMDS="npm ci && npm run build"
```

### 团队成员使用

```bash
# 团队成员切换到团队工作空间
devops env use frontend-team

# 使用团队标准配置部署
devops run vue my-frontend-app
# 自动使用团队配置的 Git 地址、Node.js 版本等
```

## 🌍 环境隔离

### 多环境工作空间

```bash
# 开发环境工作空间
devops create workspace dev-env \
  --namespace dev \
  --build-env dev \
  --build-version "jdk:17,maven:3.9.3"

# 测试环境工作空间
devops create workspace test-env \
  --namespace test \
  --build-env test \
  --build-version "jdk:11,maven:3.8.6"

# 生产环境工作空间
devops create workspace prod-env \
  --namespace production \
  --build-env prod \
  --build-version "jdk:11,maven:3.8.6"
```

### 环境切换部署

```bash
# 部署到开发环境
devops env use dev-env
devops run java my-app

# 部署到测试环境
devops env use test-env
devops run java my-app

# 部署到生产环境
devops env use prod-env
devops run java my-app
```

## 🔧 高级配置

### 自定义模板

在工作空间中添加自定义模板：

```bash
# 创建工作空间模板目录
mkdir -p workspace/my-team/templates/k8s/custom-spring-boot

# 添加自定义模板文件
cp templates/k8s/spring-boot/* workspace/my-team/templates/k8s/custom-spring-boot/

# 修改模板配置
vim workspace/my-team/templates/k8s/custom-spring-boot/deploy.yaml
```

### 环境变量配置

```bash
# workspace/my-team/config

# 自定义环境变量
CUSTOM_ENV_VAR="value"
DATABASE_URL="jdbc:mysql://db.company.com:3306/mydb"
REDIS_URL="redis://redis.company.com:6379"

# 这些变量会在构建时自动注入
```

### 构建钩子

```bash
# workspace/my-team/config

# 构建前执行的命令
PRE_BUILD_CMDS="echo 'Starting build...'"

# 构建后执行的命令
POST_BUILD_CMDS="echo 'Build completed!'"

# 部署前执行的命令
PRE_DEPLOY_CMDS="kubectl create namespace ${BUILD_NAMESPACE} --dry-run=client -o yaml | kubectl apply -f -"
```

## 🛠️ 故障排除

### 工作空间不生效

```bash
# 检查当前工作空间
devops env info

# 确认配置文件存在
ls -la workspace/my-team/config

# 检查配置文件语法
bash -n workspace/my-team/config
```

### 配置冲突

```bash
# 命令行参数会覆盖工作空间配置
devops run java my-app --build-version "jdk:11"  # 覆盖工作空间的 JDK 版本

# 查看最终生效的配置
devops run java my-app --dry-run --show-config
```

### 权限问题

```bash
# 检查工作空间目录权限
ls -la workspace/

# 修复权限问题
chmod 755 workspace/my-team/
chmod 644 workspace/my-team/config
```
