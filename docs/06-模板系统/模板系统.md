# DevOps 模板系统

DevOps 使用先进的模板系统来生成部署配置文件，支持多种部署平台和应用类型。

## 🎯 核心特性

- **Python模板渲染器**: 精确的YAML结构处理
- **多平台支持**: Kubernetes和Docker Swarm
- **丰富的模板变量**: 支持复杂的配置场景
- **条件逻辑**: 支持基于条件的模板渲染
- **安全处理**: 安全的特殊字符和多行内容处理

## 📁 模板结构

```
templates/
├── k8s/                    # Kubernetes 模板
│   ├── spring-boot/       # Spring Boot 应用模板
│   │   ├── meta.json      # 模板元数据
│   │   ├── dockerfile     # Dockerfile 模板
│   │   └── deploy.yaml    # K8s 部署模板
│   ├── vue/               # Vue.js 应用模板
│   └── nginx/             # Nginx 应用模板
└── swarm/                 # Docker Swarm 模板
    ├── spring-boot/
    ├── vue/
    └── nginx/
```

## 📝 实际模板变量

### 变量格式

模板使用 `?变量名` 格式进行变量替换（不是 `{{变量名}}`）：

### 支持的变量

| 变量名 | 说明 | 示例值 |
|--------|------|--------|
| `?module_name` | 应用名称 | `my-app` |
| `?image_path` | 完整镜像路径 | `harbor.com/project/my-app` |
| `?namespace` | Kubernetes命名空间 | `default` |
| `?app_port` | 应用端口 | `8080` |
| `?expose_port` | 暴露端口 | `30080` |
| `?harbor_secret_name` | Harbor Secret名称 | `harbor-secret` |
| `?java_opts` | Java启动参数 | `-Xmx1g -Xms512m` |
| `?network` | Docker网络名称 | `devops-network` |

### 实际模板示例

```yaml
# Spring Boot Kubernetes部署模板
apiVersion: apps/v1
kind: Deployment
metadata:
  name: ?module_name
  namespace: ?namespace
  labels:
    app: ?module_name
spec:
  template:
    spec:
      containers:
      - name: ?module_name
        image: ?image_path
        ports:
        - containerPort: ?app_port
        env:
        - name: JAVA_OPTS
          value: "?java_opts"
        - name: SERVER_PORT
          value: "?app_port"
      imagePullSecrets:
      - name: ?harbor_secret_name
---
apiVersion: v1
kind: Service
metadata:
  name: ?module_name-service
  namespace: ?namespace
spec:
  ports:
  - port: 80
    targetPort: ?app_port
```

## 🎮 使用模板

### 基本用法

```bash
# 使用默认模板
devops run java my-app

# 指定特定模板
devops run java my-app --template spring-boot-advanced

# 查看可用模板
devops template list
```

### 模板选择

```bash
# Java项目模板
devops run java app --template spring-boot      # Spring Boot (默认)
devops run java app --template spring-cloud    # Spring Cloud
devops run java app --template tomcat          # Tomcat

# Vue项目模板
devops run vue app --template vue3             # Vue 3 (默认)
devops run vue app --template vue2             # Vue 2
devops run vue app --template nuxt             # Nuxt.js
```

## 🏗️ 模板开发

### 创建新模板

```bash
# 创建模板目录
mkdir -p templates/k8s/my-template

# 创建模板文件
touch templates/k8s/my-template/meta.json
touch templates/k8s/my-template/dockerfile
touch templates/k8s/my-template/deploy.yaml
```

### 模板开发说明

**注意**：实际的模板系统比较简单，不使用复杂的元数据文件。

模板目录只需要包含：
- `dockerfile` - Dockerfile模板
- `deploy.yaml` - Kubernetes部署模板

### 实际模板语法

```yaml
# deploy.yaml 实际模板示例
apiVersion: apps/v1
kind: Deployment
metadata:
  name: ?module_name
  namespace: ?namespace
  labels:
    app: ?module_name
spec:
  replicas: 1
  selector:
    matchLabels:
      app: ?module_name
  template:
    metadata:
      labels:
        app: ?module_name
    spec:
      containers:
      - name: ?module_name
        image: ?image_path
        ports:
        - containerPort: ?app_port
        env:
        - name: JAVA_OPTS
          value: "?java_opts"
      imagePullSecrets:
      - name: ?harbor_secret_name
---
apiVersion: v1
kind: Service
metadata:
  name: ?module_name-service
  namespace: ?namespace
spec:
  selector:
    app: ?module_name
  ports:
  - port: 80
    targetPort: ?app_port
    nodePort: ?expose_port
  type: NodePort
```

## 💡 最佳实践

### 模板设计原则

1. **保持简洁**: 避免过度复杂的逻辑
2. **参数化**: 将可变部分提取为变量
3. **文档化**: 提供清晰的变量说明
4. **测试**: 验证模板在不同场景下的渲染结果

### 变量命名规范

```bash
# 推荐的变量命名
{{JOB_NAME}}        # 应用名称
{{BUILD_ENV}}       # 构建环境
{{HARBOR_ADDRESS}}  # Harbor地址

# 避免的命名
{{name}}            # 太通用
{{port1}}           # 无意义的编号
```

### 条件逻辑使用

```yaml
# 推荐：基于环境的条件配置
{{#BUILD_ENV == "prod"}}
resources:
  requests:
    memory: "1Gi"
    cpu: "500m"
  limits:
    memory: "2Gi"
    cpu: "1000m"
{{/BUILD_ENV == "prod"}}

{{#BUILD_ENV == "dev"}}
resources:
  requests:
    memory: "256Mi"
    cpu: "100m"
{{/BUILD_ENV == "dev"}}
```
