# 交互式部署功能

DevOps 支持交互式部署模式，提供引导式的配置体验，特别适合新手用户或需要逐步配置的场景。

## 🎯 核心特性

- **引导式配置**: 逐步提示输入必要参数
- **智能默认值**: 自动显示workspace配置的默认值
- **必填参数智能变可选**: workspace有默认值时自动变为可选
- **命令预览**: 显示等效的命令行形式
- **参数验证**: 实时验证输入参数的有效性

## 🚀 启动交互式部署

### 基本语法

```bash
# 完全交互式部署（会提示选择类型和项目名）
devops run -i

# 指定类型的交互式部署（会提示输入项目名）
devops run java -i
devops run vue -i

# 指定项目的交互式部署（会提示配置参数）
devops run java crm -i
devops run vue frontend -i
```

## 🔄 交互式流程

### 1. 部署类型选择

如果未指定部署类型，系统会提供友好的选择界面：

```bash
devops run -i

支持的部署类型：
  1) java   - Java项目（Spring Boot等）
  2) vue    - Vue.js前端项目
  3) go     - Go语言项目
  4) nginx  - Nginx静态项目
  5) tomcat - Tomcat Web项目

🔹 请选择部署类型（输入序号或名称）: 1
```

### 2. 项目名称输入

```bash
🔹 项目/模块名称: my-java-app
```

### 3. 代码拉取配置

```bash
代码拉取方式：
  1) Git
  2) SVN

🔹 请选择代码拉取方式（1/2）: 1

# 智能显示workspace默认值
🔸 请输入Git地址（可选，默认地址为：https://git.company.com/my-java-app.git，回车使用默认地址）: 

🔸 Git 分支 (可选，默认值为：main，回车使用默认值): 
```

### 4. 版本管理配置

```bash
# 如果workspace有默认版本配置
🔸 构建工具版本 (可选，默认值为：jdk:17,maven:3.9.3，回车使用默认值): 

# 如果workspace没有默认版本配置
构建工具版本配置 (可选):
  格式: 工具:版本,工具:版本
  示例: node:18.12,jdk:17,maven:3.9.3
  支持: node, jdk/java, maven, gradle, volta
🔸 构建工具版本 (可留空): jdk:17,maven:3.9.3
```

### 5. 部署参数配置

```bash
# 模板选择
选择模板 (可选，默认模板：spring-boot):
  回车使用默认模板，或输入自定义模板名称
🔸 部署模板: 

# 命名空间配置
🔸 Kubernetes Namespace (可选，默认值为：default，回车使用默认值): dev

# 构建环境配置
构建环境配置 (可选):
  常用环境: dev, test, staging, prod
🔸 构建环境 (可留空): prod
```

### 6. 端口配置

```bash
端口配置方式：
  1) 传统方式 - 单端口配置
  2) 多端口方式 - 支持多个服务端口和导出端口

🔸 选择端口配置方式 (1/2，默认1): 2

# 多端口配置
支持的格式：
  - 单端口: 8080
  - 多端口: 8080,9090,3000
  - 命名端口: http:8080,admin:9090
  - 混合格式: 8080,admin:9090,3000

🔸 服务端口配置 (可留空): http:8080,admin:9090
🔸 导出端口配置 (NodePort，范围30000-32767，可留空): 30080,30090
```

## 💡 智能提示特性

### 默认值显示

系统会智能显示workspace配置的默认值：

```bash
# Git地址有默认值
🔸 请输入Git地址（可选，默认地址为：https://git.company.com/crm.git，回车使用默认地址）:

# 版本配置有默认值
🔸 构建工具版本 (可选，默认值为：node:18.12,jdk:17，回车使用默认值):

# 分支有默认值
🔸 Git 分支 (可选，默认值为：main，回车使用默认值):
```

### 必填参数智能变可选

如果workspace配置了默认值，原本的必填参数会变为可选：

```bash
# 没有workspace默认值时（必填）
🔹 请输入Git地址: 

# 有workspace默认值时（可选）
🔸 请输入Git地址（可选，默认地址为：xxx，回车使用默认地址）:
```

### 格式提示和验证

系统会提供详细的格式说明和实时验证：

```bash
# 端口格式提示
支持的格式：
  - 单端口: 8080
  - 多端口: 8080,9090,3000
  - 命名端口: http:8080,admin:9090

# 版本格式提示
构建工具版本配置 (可选):
  格式: 工具:版本,工具:版本
  示例: node:18.12,jdk:17,maven:3.9.3
  支持: node, jdk/java, maven, gradle, volta
```

## 🎮 使用场景

### 场景1: 新手用户

```bash
# 完全交互式，逐步引导
devops run -i

# 系统会引导用户：
# 1. 选择部署类型
# 2. 输入项目名称
# 3. 配置代码仓库
# 4. 设置版本信息
# 5. 配置部署参数
# 6. 设置端口信息
```

### 场景2: 快速部署

```bash
# 指定项目，快速配置
devops run java crm -i

# 系统会跳过类型和名称选择，直接进入参数配置
```

### 场景3: 团队标准化

```bash
# workspace预配置默认值，团队成员只需确认
devops run vue frontend -i

# 大部分参数都有默认值，用户只需要回车确认
```

### 场景4: 复杂配置

```bash
# 需要配置多个参数的复杂项目
devops run java microservice -i

# 交互式模式可以逐步配置所有参数，避免遗漏
```

## 🔧 高级功能

### 命令预览

交互式配置完成后，系统会显示等效的命令行形式：

```bash
✅ 配置完成！等效命令行：

devops run java crm \
  --git-url https://git.company.com/crm.git \
  --git-branch main \
  --build-version "jdk:17,maven:3.9.3" \
  --build-env prod \
  --service-port "http:8080,admin:9090" \
  --export-port "30080,30090" \
  --namespace dev

🔸 是否执行部署? [Y/n]: 
```

### 配置保存

用户可以选择将配置保存为脚本：

```bash
🔸 是否保存配置为脚本? [y/N]: y
🔸 脚本文件名 (默认: deploy-crm.sh): 

✅ 配置已保存到 deploy-crm.sh
```

## 💡 最佳实践

### Workspace预配置

为团队配置常用的默认值：

```bash
# workspace/team/config
BUILD_PLATFORM="KUBERNETES"
BUILD_HARBOR_ADDRESS="harbor.company.com"
BUILD_HARBOR_PROJECT="team-project"
BUILD_VERSION="jdk:17,maven:3.9.3"
BUILD_GIT_URL="https://git.company.com"
BUILD_GIT_BRANCH="main"
```

### 分层配置策略

```bash
# 1. 全局默认值（workspace配置）
# 2. 项目特定值（命令行参数）
# 3. 环境特定值（--build-env参数）
```

### 交互式与命令行混合

```bash
# 部分参数通过命令行指定，其他参数交互式配置
devops run java crm --git-url https://custom-repo.git -i
```

## 🛠️ 故障排除

### 常见问题

**输入验证失败**：
```bash
# 错误提示
❌ 无效的端口格式: http-8080

# 解决方案
🔸 请重新输入 (格式: name:port): http:8080
```

**默认值不显示**：
```bash
# 检查workspace配置
cat workspace/current/config

# 确认配置项是否正确设置
BUILD_VERSION="jdk:17,maven:3.9.3"
```

**交互式中断**：
```bash
# 使用 Ctrl+C 可以安全退出交互式模式
# 已输入的配置不会被保存
```
