# 多端口配置功能

DevOps 支持灵活的多端口配置，可以同时配置多个服务端口和导出端口，并自动建立正确的映射关系。

## 🎯 核心特性

- **多端口支持**: 同时配置多个服务端口和NodePort
- **智能映射**: 自动建立NodePort到ServicePort的正确对应关系
- **多种格式**: 支持单端口、多端口、命名端口、混合格式
- **向后兼容**: 完全兼容传统的单端口配置方式

## 📋 端口配置参数

| 参数 | 说明 | 示例 |
|------|------|------|
| `--service-port` | 服务端口配置 | `8080` 或 `http:8080,admin:9090` |
| `--export-port` | 导出端口配置（NodePort） | `30080` 或 `http:30080,admin:30090` |
| `--app-port` | 传统应用端口（向后兼容） | `8080` |
| `--expose-port` | 传统导出端口（向后兼容） | `30080` |

## 🔧 支持的端口格式

### 单端口格式

```bash
# 单个服务端口
--service-port "8080"

# 单个导出端口
--export-port "30080"
```

### 多端口格式

```bash
# 多个服务端口
--service-port "8080,9090,3000"

# 多个导出端口
--export-port "30080,30090,30000"
```

### 命名端口格式

```bash
# 命名服务端口
--service-port "http:8080,admin:9090"

# 命名导出端口
--export-port "http:30080,admin:30090"
```

### 混合格式

```bash
# 混合服务端口
--service-port "8080,admin:9090,3000"

# 混合导出端口
--export-port "30080,admin:30090,30000"
```

## 🔄 端口映射规则

### 基本映射逻辑

端口映射**按索引顺序**进行，不是按名称匹配：

```bash
# 配置
--service-port "http:8080,admin:9090,api:3000"
--export-port "30080,30090,30000"

# 映射关系（按顺序）
service_ports[0] (http:8080)  -> export_ports[0] (30080)
service_ports[1] (admin:9090) -> export_ports[1] (30090)  
service_ports[2] (api:3000)   -> export_ports[2] (30000)
```

### 数量不匹配处理

**服务端口多于导出端口**：
```bash
--service-port "http:8080,admin:9090,api:3000"
--export-port "30080,30090"

# 结果：前两个服务端口有NodePort，第三个没有
```

**导出端口多于服务端口**：
```bash
--service-port "http:8080,admin:9090"
--export-port "30080,30090,30000"

# 结果：多余的导出端口被忽略
```

## 📝 使用示例

### Web应用多端口配置

```bash
devops run java webapp \
  --service-port "http:8080,admin:9090" \
  --export-port "http:30080,admin:30090"
```

**生成的Service配置**：
```yaml
spec:
  type: NodePort
  ports:
  - name: http
    port: 8080
    targetPort: 8080
    nodePort: 30080
    protocol: TCP
  - name: admin
    port: 9090
    targetPort: 9090
    nodePort: 30090
    protocol: TCP
```

### 微服务多端口配置

```bash
devops run vue frontend \
  --service-port "80,8080,3000" \
  --export-port "30080,30081,30082"
```

### API服务配置

```bash
devops run java api \
  --service-port "8080,health:9090,metrics:9091" \
  --export-port "30080,30090"
```

## 🎮 交互式多端口配置

在交互式部署中，系统会提供端口配置方式选择：

```bash
devops run java api -i

# 系统提示
端口配置方式：
  1) 传统方式 - 单端口配置
  2) 多端口方式 - 支持多个服务端口和导出端口

🔸 选择端口配置方式 (1/2，默认1): 2

# 多端口配置提示
支持的格式：
  - 单端口: 8080
  - 多端口: 8080,9090,3000
  - 命名端口: http:8080,admin:9090
  - 混合格式: 8080,admin:9090,3000

🔸 服务端口配置 (可留空): http:8080,admin:9090
🔸 导出端口配置 (NodePort，范围30000-32767，可留空): 30080,30090
```

## 🔍 端口验证规则

### 服务端口验证

- **范围**: 1-65535
- **格式**: 纯数字或 `名称:数字`
- **示例**: `8080`, `http:8080`

### 导出端口验证

- **范围**: 30000-32767 (NodePort范围)
- **格式**: 纯数字或 `名称:数字`
- **示例**: `30080`, `http:30080`

### 自动验证

系统会自动验证：
- 端口号范围是否正确
- 端口格式是否有效
- NodePort是否在有效范围内

## 💡 最佳实践

### 端口命名规范

```bash
# 推荐：使用有意义的端口名称
--service-port "web:80,api:8080,admin:9090"
--export-port "web:30080,api:30081,admin:30090"

# 避免：无意义的名称
--service-port "port1:80,port2:8080"
```

### 端口顺序规划

```bash
# 推荐：按重要性排序
--service-port "main:8080,admin:9090,health:8081"
--export-port "30080,30090,30081"

# 主要服务端口优先获得NodePort
```

### 端口范围规划

```bash
# 推荐：为不同环境预留端口范围
# 开发环境: 30000-30099
# 测试环境: 30100-30199
# 生产环境: 30200-30299

devops run java app --export-port "30200,30201" --build-env "prod"
```

## 🛠️ 故障排除

### 常见错误

**端口范围错误**：
```bash
# 错误
--export-port "8080"  # 不在NodePort范围内

# 正确
--export-port "30080"
```

**端口格式错误**：
```bash
# 错误
--service-port "http-8080"  # 应该使用冒号

# 正确
--service-port "http:8080"
```

**端口冲突**：
```bash
# 检查端口占用
kubectl get svc -A | grep 30080

# 使用其他端口
--export-port "30081"
```

### 调试技巧

```bash
# 查看生成的Service配置
kubectl get svc <service-name> -o yaml

# 检查端口映射
kubectl describe svc <service-name>

# 测试端口连通性
curl <node-ip>:<node-port>
```
