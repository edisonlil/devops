# 多端口配置功能

DevOps 支持灵活的多端口配置，可以同时配置多个服务端口和导出端口，并自动建立正确的映射关系。

## 🎯 核心特性

- **多端口支持**: 同时配置多个服务端口和NodePort
- **智能映射**: 支持顺序映射和显式端口映射两种模式
- **显式映射**: 通过 `服务端口:NodePort` 格式精确指定映射关系
- **部分暴露**: 可选择性暴露部分端口为NodePort
- **多种格式**: 支持单端口、多端口、命名端口、混合格式
- **向后兼容**: 完全兼容传统的单端口配置方式

## 📋 端口配置参数

| 参数 | 说明 | 示例 |
|------|------|------|
| `--service-port` | 服务端口配置 | `8080` 或 `http:8080,admin:9090` |
| `--export-port` | 导出端口配置（NodePort） | `30080` 或 `5005:31080,80:31081` |
| `--app-port` | 传统应用端口（向后兼容） | `8080` |
| `--expose-port` | 传统导出端口（向后兼容） | `30080` |

## 🔧 支持的端口格式

### 单端口格式

```bash
# 单个服务端口
--service-port "8080"

# 单个导出端口
--export-port "30080"
```

### 多端口格式

```bash
# 多个服务端口
--service-port "8080,9090,3000"

# 多个导出端口
--export-port "30080,30090,30000"
```

### 命名端口格式

```bash
# 命名服务端口
--service-port "http:8080,admin:9090"

# 命名导出端口
--export-port "http:30080,admin:30090"
```

### 显式端口映射格式

```bash
# 显式指定服务端口与NodePort的映射关系
--export-port "8080:30080,9090:30090"

# 与命名端口配合使用
--service-port "http:8080,admin:9090"
--export-port "http:30080,9090:30090"
```

### 混合格式

```bash
# 混合服务端口
--service-port "8080,admin:9090,3000"

# 混合导出端口（显式映射+顺序映射）
--export-port "8080:30080,30090,30000"
```

## 🔄 端口映射规则

### 1. 显式映射优先规则

当使用 `服务端口:NodePort` 格式时，将忽略端口顺序，直接按服务端口号或名称进行匹配：

```bash
# 配置示例
--service-port "http:80,remote-debug:5005"
--export-port "5005:31080"

# 映射结果
http:80        → 无NodePort（未显式映射）
remote-debug:5005 → NodePort:31080（按端口号显式映射）
```

### 2. 顺序映射规则

未使用显式映射时，端口将按索引顺序一一对应：

```bash
# 配置示例
--service-port "8080,9090,3000"
--export-port "30080,30090,30000"

# 映射结果（按顺序）
8080 → 30080
9090 → 30090
3000 → 30000
```

### 3. 数量不匹配处理

- **服务端口多于导出端口**：仅前面N个服务端口有NodePort
- **导出端口多于服务端口**：多余的导出端口被忽略

### 4. Service类型自动设置

- 当存在任何显式映射的NodePort时，Service类型自动设为NodePort
- 未映射NodePort的端口保持ClusterIP模式，不会被随机分配NodePort

## 🔧 功能调整说明

### 端口范围限制调整

为适应更多使用场景，当前版本已移除NodePort范围（30000-32767）限制，可以使用任意有效端口号作为NodePort

## 📝 使用示例

### 示例1：基础显式映射

```bash
# 参数配置
devops run java webapp \
  --service-port "http:8080,admin:9090,debug:5005" \
  --export-port "8080:31080,5005:31005"

# 生成配置
spec:
  ports:
  - name: http
    port: 8080
    targetPort: 8080
    nodePort: 31080  # 显式映射
  - name: admin
    port: 9090
    targetPort: 9090  # 未映射，无NodePort
  - name: debug
    port: 5005
    targetPort: 5005
    nodePort: 31005  # 显式映射
  type: NodePort  # 自动设置
```

### 示例2：部分端口暴露

```bash
# 仅暴露debug端口
devops run java api \
  --service-port "http:8080,debug:5005,metrics:9090" \
  --export-port "5005:31005"
```

### 示例3：混合映射模式

```bash
# 显式映射+顺序映射
devops run vue frontend \
  --service-port "80,443,3000" \
  --export-port "80:31080,31443"

# 映射结果
80 → 31080（显式映射）
443 → 31443（顺序映射）
3000 → 无NodePort（未映射）
```

## 🎮 交互式多端口配置

在交互式部署中，系统会提供端口配置方式选择：

```bash
devops run java api -i

# 系统提示
端口配置方式：
  1) 传统方式 - 单端口配置
  2) 多端口方式 - 支持多个服务端口和导出端口

🔸 选择端口配置方式 (1/2，默认1): 2

# 多端口配置提示
支持的格式：
  - 单端口: 8080
  - 多端口: 8080,9090,3000
  - 命名端口: http:8080,admin:9090
  - 混合格式: 8080,admin:9090,3000

🔸 服务端口配置 (可留空): http:8080,admin:9090
🔸 导出端口配置 (NodePort，范围30000-32767，可留空): 30080,30090
```

## 🔍 端口验证规则

### 服务端口验证

- **范围**: Any valid port number from 1 to 65535
- **格式**: 纯数字或 `名称:数字`
- **示例**: `8080`, `http:8080`

### 导出端口验证

- **范围**: Any valid port number from 1 to 65535 (no NodePort range restriction)
- **格式**: 纯数字, `名称:数字`, or `服务端口:NodePort`
- **示例**: `30080`, `http:30080`, `8080:30080`

### 自动验证

系统会自动验证：
- 端口号范围是否正确
- 端口格式是否有效
- NodePort是否在有效范围内

## 💡 最佳实践

### 显式映射推荐场景

1. **复杂端口配置**：当服务端口较多或顺序不固定时
2. **部分端口暴露**：仅需要暴露特定端口时
3. **固定端口策略**：需要稳定的NodePort分配时

```bash
# 推荐用法
--service-port "web:80,api:8080,admin:9090"
--export-port "web:31080,api:31808"

# 不推荐：顺序映射在端口顺序变化时易出错
--service-port "web:80,api:8080"
--export-port "31080,31808"
```

### 端口命名规范

```bash
# 推荐：使用有意义的端口名称
--service-port "web:80,api:8080,admin:9090"
--export-port "web:30080,api:30081,admin:30090"

# 避免：无意义的名称
--service-port "port1:80,port2:8080"
```

### 端口顺序规划

```bash
# 推荐：按重要性排序
--service-port "main:8080,admin:9090,health:8081"
--export-port "30080,30090,30081"

# 主要服务端口优先获得NodePort
```

### 端口范围规划

```bash
# 推荐：为不同环境预留端口范围
# 开发环境: 30000-30099
# 测试环境: 30100-30199
# 生产环境: 30200-30299

devops run java app --export-port "30200,30201" --build-env "prod"
```

## 🛠️ 故障排除

### 常见错误

**端口范围错误**：
```bash
# 错误
--export-port "8080"  # 不在NodePort范围内

# 正确
--export-port "30080"
```

**端口格式错误**：
```bash
# 错误
--service-port "http-8080"  # 应该使用冒号

# 正确
--service-port "http:8080"
```

**端口冲突**：
```bash
# 检查端口占用
kubectl get svc -A | grep 30080

# 使用其他端口
--export-port "30081"
```

### 调试技巧

```bash
# 查看生成的Service配置
kubectl get svc <service-name> -o yaml

# 检查端口映射
kubectl describe svc <service-name>

# 测试端口连通性
curl <node-ip>:<node-port>
```
