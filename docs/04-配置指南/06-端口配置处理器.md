# 端口配置处理器

端口配置处理器 (`port_config_handler.py`) 是 DevOps 工具的核心组件，负责处理 Kubernetes YAML 文件中的端口配置，支持多端口、多容器、显式映射等高级功能。

## 🎯 主要功能

- **多端口配置**: 同时配置多个服务端口和 NodePort
- **多容器支持**: 智能识别主容器，支持指定容器的端口配置
- **显式映射**: 精确控制 servicePort:nodePort 映射关系
- **自动同步**: 自动同步 Deployment containerPort 和 Service 端口
- **Sidecar识别**: 自动排除 Istio、日志收集等 sidecar 容器
- **端口验证**: 自动验证端口配置的有效性

## 📋 命令行参数

### 基本参数

| 参数 | 必需 | 说明 |
|------|------|------|
| `--yaml-file` | ✅ | 要处理的 YAML 文件路径 |

### 端口配置参数

| 参数 | 说明 | 示例 |
|------|------|------|
| `--service-port` | 服务端口配置，支持容器指定 | `http:8080,admin:9090` 或 `web-app:http:8080` |
| `--export-port` | 导出端口配置，支持显式映射 | `30080,30090` 或 `8080:30080,9090:30090` |

### 传统参数（向后兼容）

| 参数 | 说明 | 示例 |
|------|------|------|
| `--expose-port` | 传统单端口暴露 | `30080` |
| `--force-port` | 强制覆盖端口 | - |

### 功能参数

| 参数 | 说明 |
|------|------|
| `--validate` | 验证端口配置 |
| `--info` | 显示端口信息 |

## 🔧 支持的端口格式

### service-port 格式

```bash
# 基础格式
--service-port "8080"                    # 单端口
--service-port "8080,9090,3000"          # 多端口
--service-port "http:8080,admin:9090"    # 命名端口

# 容器指定格式
--service-port "web-app:http:8080,api-service:api:3000"
--service-port "http:8080,sidecar:metrics:9090"  # 混合格式
```

### export-port 格式

```bash
# 基础格式
--export-port "30080"                    # 单端口
--export-port "30080,30090,30300"        # 多端口
--export-port "http:30080,admin:30090"   # 命名端口

# 显式映射格式
--export-port "8080:30080,9090:30090"    # servicePort:nodePort
--export-port "9090:31090,30080,30300"   # 混合显式和顺序映射
```

## 🐳 多容器支持

### 自动主容器识别

系统会自动识别并排除以下 sidecar 容器：

- **服务网格**: `istio-proxy`, `envoy`, `proxy`
- **日志收集**: `fluentd`, `filebeat`, `logstash`, `logging`
- **监控组件**: `prometheus`, `metrics`, `monitoring`
- **链路追踪**: `jaeger`, `zipkin`, `tracing`

### 容器指定语法

```bash
# 格式：容器名:端口名:端口号
--service-port "web-app:http:8080,api-service:api:3000,monitoring:metrics:9090"
```

### 自动 containerPort 同步

1. **添加缺失端口**: 自动添加不存在的 containerPort
2. **更新端口名称**: 同步端口名称保持一致性
3. **避免重复**: 不会重复添加已存在的端口

## 📝 使用示例

### 基础多端口配置

```bash
# 多端口配置
python bin/port_config_handler.py \
  --yaml-file deploy.yaml \
  --service-port "http:8080,admin:9090,health:8081" \
  --export-port "30080,30090,30081"
```

### 显式端口映射

```bash
# 精确控制端口映射
python bin/port_config_handler.py \
  --yaml-file deploy.yaml \
  --service-port "http:8080,admin:9090,debug:5005" \
  --export-port "8080:30080,5005:31005"
```

### 多容器端口配置

```bash
# 指定容器的端口配置
python bin/port_config_handler.py \
  --yaml-file deploy.yaml \
  --service-port "web-app:http:8080,api-service:api:3000,monitoring:metrics:9090" \
  --export-port "8080:30080,3000:30300"
```

### 混合映射配置

```bash
# 显式映射 + 顺序映射
python bin/port_config_handler.py \
  --yaml-file deploy.yaml \
  --service-port "web:8080,admin:9090,api:3000,metrics:4000" \
  --export-port "9090:31090,30080,4000:31400,30300"
```

## 🔄 端口映射规则

### 1. 显式映射优先

使用 `servicePort:nodePort` 格式的显式映射具有最高优先级：

```bash
--service-port "http:8080,admin:9090,api:3000"
--export-port "9090:31090,30080,30300"

# 结果：
# http:8080 → NodePort 30080 (顺序映射)
# admin:9090 → NodePort 31090 (显式映射)
# api:3000 → NodePort 30300 (顺序映射)
```

### 2. 顺序映射规则

未使用显式映射时，按索引顺序一一对应：

```bash
--service-port "8080,9090,3000"
--export-port "30080,30090,30300"

# 结果：
# 8080 → 30080
# 9090 → 30090  
# 3000 → 30300
```

### 3. 数量不匹配处理

- **服务端口多于导出端口**: 仅前面N个服务端口有NodePort
- **导出端口多于服务端口**: 多余的导出端口被忽略

### 4. Service类型自动设置

- 当存在任何 NodePort 配置时，Service 类型自动设为 NodePort
- 未映射 NodePort 的端口保持 ClusterIP 模式

## 💡 最佳实践

### 1. 使用有意义的端口名称

```bash
# 推荐
--service-port "web:80,api:8080,admin:9090"

# 避免
--service-port "port1:80,port2:8080"
```

### 2. 显式映射用于关键端口

```bash
# 推荐：关键端口使用显式映射
--service-port "web:80,api:8080,admin:9090"
--export-port "web:30080,api:30081"
```

### 3. 多容器场景明确指定

```bash
# 推荐：明确指定容器
--service-port "web-app:http:8080,api-service:api:3000"

# 可选：依赖自动识别
--service-port "http:8080,api:3000"
```

## 🛠️ 故障排除

### 常见错误

1. **端口格式错误**
   ```bash
   # 错误
   --service-port "http-8080"
   
   # 正确
   --service-port "http:8080"
   ```

2. **容器名称不存在**
   ```bash
   # 检查容器名称
   kubectl get deployment <name> -o yaml | grep -A 10 containers
   ```

3. **端口冲突**
   ```bash
   # 检查端口占用
   kubectl get svc -A | grep <port>
   ```

### 调试技巧

```bash
# 查看详细日志
python bin/port_config_handler.py --yaml-file deploy.yaml --service-port "..." --info

# 验证配置
python bin/port_config_handler.py --yaml-file deploy.yaml --validate

# 查看生成的配置
kubectl get svc <service-name> -o yaml
```
