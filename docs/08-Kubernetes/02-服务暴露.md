# Kubernetes 服务暴露

DevOps 提供了灵活的 Kubernetes 服务暴露功能，支持多种服务类型和端口配置方式。

## 🎯 核心特性

- **多种服务类型**: 支持 ClusterIP、NodePort、LoadBalancer
- **多端口配置**: 支持单端口和多端口服务
- **智能端口映射**: 自动建立NodePort到ServicePort的映射关系
- **命名端口支持**: 支持有意义的端口命名

## 📋 服务类型

### ClusterIP（默认）

集群内部访问，不对外暴露：

```bash
# 创建ClusterIP服务（默认）
devops run java app --service-port "8080"
```

生成的Service：
```yaml
apiVersion: v1
kind: Service
metadata:
  name: app-service
spec:
  type: ClusterIP
  ports:
  - port: 8080
    targetPort: 8080
    protocol: TCP
  selector:
    app: app
```

### NodePort

通过节点端口对外暴露：

```bash
# 创建NodePort服务
devops run java app --service-port "8080" --export-port "30080"
```

生成的Service：
```yaml
apiVersion: v1
kind: Service
metadata:
  name: app-service
spec:
  type: NodePort
  ports:
  - port: 8080
    targetPort: 8080
    nodePort: 30080
    protocol: TCP
  selector:
    app: app
```

## 🔧 端口配置

### 单端口配置

```bash
# 传统单端口方式
devops run java app --app-port 8080 --expose-port 30080

# 新的单端口方式
devops run java app --service-port "8080" --export-port "30080"
```

### 多端口配置

```bash
# 多个端口
devops run java app \
  --service-port "8080,9090,3000" \
  --export-port "30080,30090,30000"

# 命名端口
devops run java app \
  --service-port "http:8080,admin:9090,health:8081" \
  --export-port "http:30080,admin:30090,health:30081"
```

生成的多端口Service：
```yaml
apiVersion: v1
kind: Service
metadata:
  name: app-service
spec:
  type: NodePort
  ports:
  - name: http
    port: 8080
    targetPort: 8080
    nodePort: 30080
    protocol: TCP
  - name: admin
    port: 9090
    targetPort: 9090
    nodePort: 30090
    protocol: TCP
  - name: health
    port: 8081
    targetPort: 8081
    nodePort: 30081
    protocol: TCP
  selector:
    app: app
```

## 🔄 端口映射规则

### 映射逻辑

端口映射按**索引顺序**进行：

```bash
# 配置
--service-port "web:80,api:8080,admin:9090"
--export-port "30080,30081,30090"

# 映射关系
web:80 (index 0)    -> 30080 (index 0)
api:8080 (index 1)  -> 30081 (index 1)
admin:9090 (index 2) -> 30090 (index 2)
```

### 数量不匹配处理

**服务端口多于导出端口**：
```bash
--service-port "80,8080,9090"
--export-port "30080"

# 结果：只有第一个端口(80)有NodePort
```

**导出端口多于服务端口**：
```bash
--service-port "80,8080"
--export-port "30080,30081,30090"

# 结果：多余的导出端口(30090)被忽略
```

## 🎮 服务发现

### 集群内访问

```bash
# 通过Service名称访问
curl http://app-service:8080

# 通过完整域名访问
curl http://app-service.default.svc.cluster.local:8080

# 跨命名空间访问
curl http://app-service.production.svc.cluster.local:8080
```

### 外部访问

```bash
# 通过NodePort访问
curl http://<node-ip>:30080

# 查看节点IP
kubectl get nodes -o wide

# 查看NodePort
kubectl get svc app-service
```

## 🔍 服务管理

### 查看服务

```bash
# 查看所有服务
kubectl get svc

# 查看特定命名空间的服务
kubectl get svc -n production

# 查看服务详细信息
kubectl describe svc app-service
```

### 服务测试

```bash
# 测试服务连通性
kubectl run test-pod --image=busybox --rm -it -- sh
# 在pod内执行
wget -qO- http://app-service:8080

# 端口转发测试
kubectl port-forward svc/app-service 8080:8080
# 本地访问 http://localhost:8080
```

### 服务更新

```bash
# 更新服务端口
kubectl patch svc app-service -p '{"spec":{"ports":[{"port":8080,"targetPort":8080,"nodePort":30080}]}}'

# 重新部署更新服务
devops run java app --service-port "8080,9090" --export-port "30080,30090"
```

## 💡 最佳实践

### 端口规划

```bash
# 为不同环境预留端口范围
# 开发环境: 30000-30099
# 测试环境: 30100-30199
# 生产环境: 30200-30299

devops run java app --export-port "30200" --build-env "prod"
```

### 服务命名

```bash
# 使用有意义的端口名称
--service-port "web:80,api:8080,admin:9090,health:8081"

# 避免通用名称
--service-port "port1:80,port2:8080"  # 不推荐
```

### 健康检查端口

```bash
# 为健康检查单独配置端口
--service-port "http:8080,health:8081"
--export-port "30080"  # 只暴露主要服务端口
```

### 安全考虑

```bash
# 管理端口不对外暴露
--service-port "web:80,admin:9090"
--export-port "30080"  # 只暴露web端口，admin端口仅集群内访问
```

## 🛠️ 故障排除

### 常见问题

**端口冲突**：
```bash
# 检查端口占用
kubectl get svc -A | grep 30080

# 使用其他端口
--export-port "30081"
```

**服务无法访问**：
```bash
# 检查服务状态
kubectl get svc app-service

# 检查端点
kubectl get endpoints app-service

# 检查Pod标签
kubectl get pods --show-labels
```

**NodePort无法访问**：
```bash
# 检查防火墙规则
sudo ufw status
sudo firewall-cmd --list-ports

# 检查节点端口范围
kubectl describe node | grep NodePort
```

### 调试技巧

```bash
# 查看服务事件
kubectl get events --field-selector involvedObject.name=app-service

# 测试服务解析
nslookup app-service.default.svc.cluster.local

# 检查网络策略
kubectl get networkpolicies -n default
```
