# Kubernetes 命名空间管理

DevOps 提供了完整的 Kubernetes 命名空间管理功能，支持自动创建、配置和管理命名空间。

## 🎯 核心特性

- **自动命名空间创建**: 部署时自动创建不存在的命名空间
- **Harbor Secret管理**: 自动创建和管理镜像拉取凭证
- **命名空间隔离**: 支持多环境、多团队的资源隔离
- **权限管理**: 基于命名空间的访问控制

## 📋 命名空间配置

### 基本用法

```bash
# 指定命名空间部署
devops run java app --namespace dev

# 如果命名空间不存在，会自动创建
devops run java app --namespace new-namespace
```

### Workspace默认命名空间

```bash
# 在workspace配置中设置默认命名空间
# workspace/team/config
BUILD_NAMESPACE="team-dev"

# 使用时自动应用默认命名空间
devops run java app  # 自动使用 team-dev 命名空间
```

## 🔧 自动创建功能

### 命名空间自动创建

当指定的命名空间不存在时，系统会：

1. **检查命名空间**: 验证命名空间是否存在
2. **创建命名空间**: 自动创建新的命名空间
3. **配置标签**: 添加管理标签和注释
4. **创建Secret**: 自动创建Harbor镜像拉取凭证

```bash
# 示例：部署到新命名空间
devops run java app --namespace new-project

# 系统输出
INFO: 命名空间 'new-project' 不存在，正在创建...
INFO: 命名空间 'new-project' 创建成功
INFO: 正在为命名空间 'new-project' 创建Harbor Secret...
INFO: Harbor Secret 创建成功
```

### 创建的资源

自动创建命名空间时会包含：

```yaml
# Namespace
apiVersion: v1
kind: Namespace
metadata:
  name: new-project
  labels:
    managed-by: devops
    created-by: devops-auto
  annotations:
    devops.io/created-at: "2024-01-01T00:00:00Z"
    devops.io/workspace: "current-workspace"

---
# Harbor Secret (如果配置了Harbor)
apiVersion: v1
kind: Secret
metadata:
  name: harbor-secret
  namespace: new-project
type: kubernetes.io/dockerconfigjson
data:
  .dockerconfigjson: <base64-encoded-config>
```

## 🏗️ Harbor集成

### 自动Secret管理

DevOps 会自动为新命名空间创建Harbor镜像拉取凭证：

```bash
# 配置Harbor信息（在workspace中）
BUILD_HARBOR_ADDRESS="harbor.company.com"
BUILD_HARBOR_USERNAME="robot$project+deploy"
BUILD_HARBOR_PASSWORD="your-robot-token"

# 部署时自动创建Harbor Secret
devops run java app --namespace production
```

### Secret验证和更新

```bash
# 验证Harbor Secret状态
devops env harbor-secret --namespace dev

# 更新Harbor Secret
devops env harbor-secret --namespace dev --update
```

## 🎮 命名空间管理命令

### 查看命名空间

```bash
# 列出所有命名空间
kubectl get namespaces

# 查看DevOps管理的命名空间
kubectl get namespaces -l managed-by=devops
```

### 手动创建命名空间

```bash
# 使用DevOps创建命名空间（包含Harbor Secret）
devops create namespace my-project

# 为现有命名空间添加Harbor Secret
devops env harbor-secret --namespace existing-ns
```

### 删除命名空间

```bash
# 删除命名空间（谨慎操作）
kubectl delete namespace my-project

# 删除前备份重要资源
kubectl get all -n my-project -o yaml > backup.yaml
```

## 🔒 权限和安全

### RBAC配置

为命名空间配置适当的RBAC权限：

```yaml
# 示例：为开发团队配置命名空间权限
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: dev-team-binding
  namespace: dev-project
subjects:
- kind: User
  name: dev-user
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: ClusterRole
  name: edit
  apiGroup: rbac.authorization.k8s.io
```

### 网络策略

```yaml
# 示例：命名空间网络隔离
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-all
  namespace: production
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  - Egress
```

## 💡 最佳实践

### 命名空间命名规范

```bash
# 推荐的命名规范
<team>-<environment>     # team-dev, team-prod
<project>-<environment>  # crm-dev, crm-staging
<department>-<purpose>   # finance-reports, hr-tools
```

### 环境隔离策略

```bash
# 开发环境
devops run java app --namespace dev --build-env dev

# 测试环境
devops run java app --namespace test --build-env test

# 生产环境
devops run java app --namespace prod --build-env prod
```

### 资源配额管理

```yaml
# 为命名空间设置资源配额
apiVersion: v1
kind: ResourceQuota
metadata:
  name: compute-quota
  namespace: dev-project
spec:
  hard:
    requests.cpu: "4"
    requests.memory: 8Gi
    limits.cpu: "8"
    limits.memory: 16Gi
    pods: "10"
```

## 🛠️ 故障排除

### 常见问题

**命名空间创建失败**：
```bash
# 检查权限
kubectl auth can-i create namespaces

# 检查集群状态
kubectl cluster-info
```

**Harbor Secret创建失败**：
```bash
# 检查Harbor配置
devops env info | grep HARBOR

# 手动测试Harbor连接
docker login harbor.company.com
```

**权限不足**：
```bash
# 检查当前用户权限
kubectl auth can-i "*" --namespace target-namespace

# 查看RBAC配置
kubectl get rolebindings -n target-namespace
```

### 调试技巧

```bash
# 查看命名空间详细信息
kubectl describe namespace my-project

# 查看命名空间中的所有资源
kubectl get all -n my-project

# 查看事件日志
kubectl get events -n my-project --sort-by='.lastTimestamp'
```
