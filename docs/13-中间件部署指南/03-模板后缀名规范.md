# 03-模板后缀名规范

## 概述

为了更好地区分和处理不同类型的模板文件，DevOps中间件部署系统采用了基于后缀名的模板类型识别机制。

## 📋 后缀名规范

### 支持的模板后缀名

| 后缀名 | 模板类型 | 语法 | 用途 | 示例 |
|--------|----------|------|------|------|
| `.yaml.j2` | Jinja2模板 | `{{ variable }}`, `{% if %}` | 复杂逻辑、条件渲染 | `deploy.yaml.j2` |
| `.yaml.tpl` | 占位符模板 | `?variable` | 简单变量替换 | `deploy.yaml.tpl` |
| `.yaml` | 自动检测 | 混合或未知 | 向后兼容 | `deploy.yaml` |

### 模板检测优先级

系统按以下优先级查找模板文件：

1. **`deploy.yaml.j2`** - Jinja2模板（最高优先级）
2. **`deploy.yaml.tpl`** - 占位符模板
3. **`deploy.yaml`** - 自动检测类型（向后兼容）

## 🎯 Jinja2模板 (`.yaml.j2`)

### 特点
- 支持完整的Jinja2语法
- 条件渲染、循环、过滤器
- 强大的模板继承和包含功能
- 严格的变量检查

### 语法示例
```yaml
# 变量替换
name: {{ instance_name }}-redis
namespace: {{ namespace }}

# 条件渲染
{% if redis_password != 'auto-generate' %}
requirepass {{ redis_password }}
{% endif %}

# 循环
{% for port in service_ports %}
- port: {{ port }}
{% endfor %}

# 过滤器
password: {{ redis_password | b64encode }}
```

### 适用场景
- 需要条件逻辑的模板
- 复杂的配置生成
- 需要数据转换的场景
- 新开发的中间件模板

## 🔧 占位符模板 (`.yaml.tpl`)

### 特点
- 简单的字符串替换
- 轻量级处理
- 向后兼容
- 处理速度快

### 语法示例
```yaml
# 变量替换
name: ?instance_name-mysql
namespace: ?namespace
replicas: ?replicas
```

### 适用场景
- 简单的变量替换
- 现有的占位符模板
- 不需要复杂逻辑的场景
- 快速原型开发

## 📁 模板文件组织

### 标准目录结构
```
templates/k8s/middleware/{middleware-name}/
├── metadata.yaml           # 模板元数据
├── deploy.yaml.j2          # Jinja2部署模板（推荐）
├── deploy.yaml.tpl         # 占位符部署模板（可选）
├── service.yaml.j2         # 服务模板（可选）
└── configmap.yaml.j2       # 配置映射模板（可选）
```

### 文件命名约定
- **主部署模板**: `deploy.yaml.j2` 或 `deploy.yaml.tpl`
- **服务模板**: `service.yaml.j2` 或 `service.yaml.tpl`
- **配置模板**: `configmap.yaml.j2` 或 `configmap.yaml.tpl`
- **存储模板**: `storage.yaml.j2` 或 `storage.yaml.tpl`

## 🔄 模板迁移指南

### 从占位符模板迁移到Jinja2

1. **重命名文件**
   ```bash
   mv deploy.yaml deploy.yaml.tpl  # 保留原版本
   cp deploy.yaml.tpl deploy.yaml.j2  # 创建新版本
   ```

2. **转换语法**
   ```bash
   # 占位符语法 → Jinja2语法
   ?instance_name → {{ instance_name }}
   ?namespace → {{ namespace }}
   ?replicas → {{ replicas }}
   ```

3. **添加条件逻辑**
   ```yaml
   # 原来的静态配置
   nodePort: ?export_port
   
   # 改为条件配置
   {% if export_port %}
   nodePort: {{ export_port }}
   {% endif %}
   ```

4. **测试验证**
   ```bash
   # 测试新模板
   devops run middleware redis-standalone test-redis -i
   ```

## 🛠️ 开发建议

### 新模板开发
- **优先使用** `.yaml.j2` 后缀
- 充分利用Jinja2的条件和循环功能
- 使用过滤器进行数据转换
- 添加注释说明复杂逻辑

### 现有模板维护
- 保持 `.yaml.tpl` 文件的向后兼容性
- 逐步迁移到 `.yaml.j2` 格式
- 同时提供两种格式以支持不同需求

### 最佳实践
1. **模板文档化**: 在模板中添加注释说明
2. **变量验证**: 使用Jinja2的严格模式检查变量
3. **测试覆盖**: 为每个模板创建测试用例
4. **版本管理**: 使用Git跟踪模板变更

## 🔍 故障排除

### 常见问题

**Q: 模板文件找不到**
```
错误: 未找到中间件模板文件
```
**A**: 检查文件名是否符合规范，确保使用正确的后缀名

**Q: Jinja2语法错误**
```
错误: Jinja2模板渲染失败
```
**A**: 检查模板语法，确保变量名正确，条件语句完整

**Q: 变量未定义**
```
错误: 'variable_name' is undefined
```
**A**: 检查变量是否在metadata.yaml中定义，或在命令行中提供
