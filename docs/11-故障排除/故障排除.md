# 故障排除指南

本指南帮助您诊断和解决使用 DevOps 工具链时遇到的常见问题。

## 🔍 问题诊断流程

### 1. 收集信息

```bash
# 查看 DevOps 版本
devops --version

# 查看当前环境信息
devops env info

# 查看系统信息
kubectl version --client
docker --version
```

### 2. 检查日志

```bash
# 查看应用日志
kubectl logs -l app=my-app -n dev --tail=100

# 查看系统事件
kubectl get events -n dev --sort-by='.lastTimestamp'

# 查看构建日志（如果有）
docker logs <container-id>
```

### 3. 验证配置

```bash
# 检查工作空间配置
cat workspace/current/config

# 验证 YAML 语法
kubectl apply --dry-run=client -f deploy.yaml

# 检查网络连通性
ping harbor.company.com
```

## 🚨 常见问题及解决方案

### 安装和环境问题

#### 问题：DevOps 命令未找到

**症状**：
```bash
$ devops --version
bash: devops: command not found
```

**解决方案**：
```bash
# 1. 检查安装路径
ls -la /usr/local/bin/devops

# 2. 检查环境变量
echo $PATH | grep -o '/usr/local/bin'

# 3. 重新安装
curl -fsSL https://github.com/edisonlil/devops/raw/refs/heads/dev/install.sh | bash

# 4. 手动添加到 PATH
echo 'export PATH="/usr/local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

#### 问题：Python 依赖缺失

**症状**：
```bash
ERROR: Python module 'yaml' not found
```

**解决方案**：
```bash
# 安装 PyYAML
pip3 install PyYAML

# 或使用系统包管理器
sudo apt-get install python3-yaml  # Ubuntu/Debian
sudo yum install python3-PyYAML    # CentOS/RHEL
```

### 部署问题

#### 问题：镜像拉取失败

**症状**：
```bash
Failed to pull image "harbor.company.com/project/app:latest": 
Error response from daemon: unauthorized
```

**解决方案**：
```bash
# 1. 检查 Harbor 登录
devops env harbor-login

# 2. 验证 Harbor Secret
kubectl get secret harbor-secret -n dev

# 3. 重新创建 Secret
devops env harbor-secret --namespace dev --update

# 4. 手动测试镜像拉取
docker pull harbor.company.com/project/app:latest
```

#### 问题：Pod 启动失败

**症状**：
```bash
$ kubectl get pods -n dev
NAME                     READY   STATUS             RESTARTS   AGE
my-app-xxx-yyy          0/1     CrashLoopBackOff   3          2m
```

**诊断步骤**：
```bash
# 1. 查看 Pod 详细信息
kubectl describe pod my-app-xxx-yyy -n dev

# 2. 查看容器日志
kubectl logs my-app-xxx-yyy -n dev

# 3. 检查资源限制
kubectl get pod my-app-xxx-yyy -n dev -o yaml | grep -A 10 resources

# 4. 检查健康检查配置
kubectl get pod my-app-xxx-yyy -n dev -o yaml | grep -A 5 livenessProbe
```

**常见解决方案**：
```bash
# 内存不足
kubectl patch deployment my-app -n dev -p '{"spec":{"template":{"spec":{"containers":[{"name":"my-app","resources":{"limits":{"memory":"1Gi"}}}]}}}}'

# 端口配置错误
kubectl patch deployment my-app -n dev -p '{"spec":{"template":{"spec":{"containers":[{"name":"my-app","ports":[{"containerPort":8080}]}]}}}}'

# 环境变量问题
kubectl set env deployment/my-app -n dev JAVA_OPTS="-Xmx512m"
```

#### 问题：服务无法访问

**症状**：
```bash
$ curl http://node-ip:30080
curl: (7) Failed to connect to node-ip port 30080: Connection refused
```

**诊断步骤**：
```bash
# 1. 检查服务配置
kubectl get svc -n dev
kubectl describe svc my-app-service -n dev

# 2. 检查端点
kubectl get endpoints my-app-service -n dev

# 3. 检查 Pod 标签
kubectl get pods --show-labels -n dev

# 4. 测试集群内访问
kubectl run test-pod --image=busybox --rm -it -- sh
wget -qO- http://my-app-service:8080
```

**解决方案**：
```bash
# 修复服务选择器
kubectl patch svc my-app-service -n dev -p '{"spec":{"selector":{"app":"my-app"}}}'

# 修复端口配置
kubectl patch svc my-app-service -n dev -p '{"spec":{"ports":[{"port":8080,"targetPort":8080,"nodePort":30080}]}}'

# 检查防火墙
sudo ufw status
sudo firewall-cmd --list-ports
```

### 构建问题

#### 问题：Git 克隆失败

**症状**：
```bash
ERROR: Failed to clone repository: Permission denied (publickey)
```

**解决方案**：
```bash
# 1. 检查 Git 配置
git config --global user.name
git config --global user.email

# 2. 检查 SSH 密钥
ssh -T git@github.com
ssh -T git@git.company.com

# 3. 使用 HTTPS 替代 SSH
devops run java my-app --git-url https://github.com/user/repo.git

# 4. 配置 Git 凭证
git config --global credential.helper store
```

#### 问题：构建工具版本错误

**症状**：
```bash
ERROR: Java version mismatch. Required: 17, Found: 11
```

**解决方案**：
```bash
# 1. 检查当前版本
java -version
mvn -version

# 2. 使用版本管理器切换
sdk use java 17.0.7-tem
nvm use 18.12

# 3. 在部署时指定版本
devops run java my-app --build-version "jdk:17,maven:3.9.3"

# 4. 更新工作空间默认版本
echo 'BUILD_VERSION="jdk:17,maven:3.9.3"' >> workspace/current/config
```

### 网络问题

#### 问题：Harbor 连接超时

**症状**：
```bash
ERROR: Failed to connect to harbor.company.com: Connection timed out
```

**解决方案**：
```bash
# 1. 检查网络连通性
ping harbor.company.com
telnet harbor.company.com 443

# 2. 检查 DNS 解析
nslookup harbor.company.com
dig harbor.company.com

# 3. 检查代理设置
echo $HTTP_PROXY
echo $HTTPS_PROXY

# 4. 配置 Docker 代理（如需要）
sudo mkdir -p /etc/systemd/system/docker.service.d
sudo tee /etc/systemd/system/docker.service.d/http-proxy.conf <<EOF
[Service]
Environment="HTTP_PROXY=http://proxy.company.com:8080"
Environment="HTTPS_PROXY=http://proxy.company.com:8080"
EOF
sudo systemctl daemon-reload
sudo systemctl restart docker
```

### 权限问题

#### 问题：Kubernetes 权限不足

**症状**：
```bash
ERROR: User cannot create resource "deployments" in API group "apps"
```

**解决方案**：
```bash
# 1. 检查当前用户权限
kubectl auth can-i create deployments --namespace dev
kubectl auth can-i "*" --namespace dev

# 2. 查看当前用户信息
kubectl config current-context
kubectl config view --minify

# 3. 联系管理员分配权限
# 需要管理员执行：
kubectl create rolebinding dev-admin \
  --clusterrole=admin \
  --user=your-username \
  --namespace=dev
```

## 🔧 调试工具

### 日志分析

```bash
# 实时查看日志
kubectl logs -f deployment/my-app -n dev

# 查看多个 Pod 日志
kubectl logs -l app=my-app -n dev --tail=100 -f

# 查看前一个容器的日志
kubectl logs my-app-xxx-yyy -n dev --previous
```

### 网络调试

```bash
# 创建调试 Pod
kubectl run debug-pod --image=nicolaka/netshoot --rm -it -- bash

# 在调试 Pod 中测试连通性
nslookup my-app-service
curl -v http://my-app-service:8080
telnet my-app-service 8080
```

```bash

kubectl top nodes
kubectl top pods -n dev

kubectl describe quota -n dev

kubectl describe limitrange -n dev
```

### 定期维护

```bash

docker system prune -a

# 清理未使用的 Kubernetes 资源
kubectl delete pods --field-selector=status.phase=Succeeded -n dev

# 更新工具版本
devops install-tools --check
```

### 监控和告警

