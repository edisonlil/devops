# DevOps 架构设计

## 🎯 核心理念

**模板驱动 + 工作空间配置 + 直接部署**

- **模板系统**：提供标准化的部署模板，支持多种应用类型
- **工作空间管理**：团队级别的配置管理和环境隔离
- **直接部署**：基于模板和参数直接生成并部署应用
- **Python增强**：使用Python模板渲染器提供精确的YAML处理

## 🔄 实际工作流程

### 1. 工作空间管理

```bash
# 创建工作空间
devops create workspace my-team \
  --platform KUBERNETES \
  --namespace dev \
  --git-url https://git.company.com \
  --build-version "jdk:17,maven:3.9.3"

# 切换工作空间
devops env use my-team

# 查看当前环境信息
devops env info
```

### 2. 直接部署应用

```bash
# Java应用部署（使用工作空间默认配置）
devops run java my-app

# 完整参数部署
devops run java my-app \
  --git-url https://github.com/company/my-app.git \
  --git-branch main \
  --build-version "jdk:17,maven:3.9.3" \
  --service-port "http:8080,admin:9090" \
  --export-port "30080,30090" \
  --namespace production

# 交互式部署
devops run java my-app -i
```

### 3. 多端口配置

```bash
# 多端口服务部署
devops run java microservice \
  --service-port "web:8080,admin:9090,health:8081" \
  --export-port "30080,30090,30081"

# 查看部署状态
kubectl get pods -n dev
kubectl get svc -n dev
```


### 模板变量系统

模板使用 `{{变量名}}` 格式进行变量替换：

**实际支持的变量**：
- `?module_name` - 应用名称
- `?image_path` - 完整镜像路径
- `?namespace` - Kubernetes命名空间
- `?app_port` - 应用端口
- `?expose_port` - 暴露端口
- `?harbor_secret_name` - Harbor Secret名称
- `?java_opts` - Java启动参数
- `?network` - Docker网络名称

**变量映射关系**：
```
用户参数 → 内部变量 → 模板变量
JOB_NAME → module_name → ?module_name
HARBOR_ADDRESS/PROJECT → image_path → ?image_path
APP_PORT → app_port → ?app_port
EXPOSE_PORT → expose_port → ?expose_port
```

**模板示例**：
```yaml
# 实际的模板格式
apiVersion: apps/v1
kind: Deployment
metadata:
  name: ?module_name
  namespace: ?namespace
spec:
  template:
    spec:
      containers:
      - name: ?module_name
        image: ?image_path
        ports:
        - containerPort: ?app_port
```

## 🎨 设计原则

### 1. 模块化设计
- **模板独立**：每个模板都是独立的，可以单独维护和版本控制
- **参数驱动**：通过参数配置实现模板的灵活复用
- **插件化架构**：支持自定义模板和扩展功能

### 2. 工作空间隔离
- **环境隔离**：不同工作空间对应不同的部署环境
- **配置独立**：每个工作空间有独立的配置文件
- **资源分离**：避免不同环境之间的资源冲突

### 3. 模板标准化
- **统一格式**：所有模板遵循相同的元数据格式
- **版本控制**：模板支持版本管理和升级
- **验证机制**：提供模板验证和测试功能

## 🔧 技术架构

### 1. 核心组件

#### Shell脚本框架
- **devops主命令**：统一的命令入口和参数解析
- **build.sh**：核心构建和部署逻辑
- **env.sh**：环境变量和参数处理
- **tools.sh**：通用工具函数库
- **workspace.sh**：工作空间管理逻辑

#### Python增强组件
- **template_renderer.py**：精确的YAML模板渲染器
- **port_config_handler.py**：统一的端口配置处理器
- **多端口支持**：智能的端口映射和验证

#### 版本管理系统
- **version_manager.sh**：构建工具版本管理
- **多版本管理器集成**：nvm、sdkman、volta等
- **工作空间版本配置**：团队级别的版本标准化

#### 模板系统
- **分层模板结构**：k8s和swarm平台分离
- **变量替换系统**：支持复杂的条件逻辑
- **Python渲染引擎**：安全的特殊字符处理

### 2. 架构特点

#### 混合架构设计
- **Shell + Python**：Shell负责流程控制，Python负责复杂处理
- **模块化设计**：每个功能模块独立，便于维护
- **向后兼容**：保持传统参数支持，同时提供新功能

#### 配置层次结构
```
命令行参数 (最高优先级)
    ↓
工作空间配置 (团队默认值)
    ↓
系统默认值 (最低优先级)
```

## 📊 实际数据流

### 1. 部署执行流程

```
用户命令 → 参数解析 → 工作空间配置加载 → 版本管理 → 模板选择 →
Python渲染 → 端口配置 → Docker构建 → Kubernetes部署 → 状态反馈
```

### 2. 多端口配置流程

```
端口参数 → 格式解析 → 端口验证 → 映射关系建立 →
YAML生成 → Service配置 → NodePort分配
```

### 3. 工作空间管理流程

```
工作空间创建 → 配置文件生成 → 环境变量设置 →
默认值应用 → 团队配置同步
```
